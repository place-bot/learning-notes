# DS2 block dependency proposal is gradually dismantled

## Select column block

Select one column \(k\) evenly from the \(K\) column, and then select \(B\) items from the \(J\) item positions without replacement, forming

\[
Q_{k,B}.
\]

All elements outside the current column block remain unchanged.

## Step 1: Protect unit rows within the block

If the other \(K-1\) columns of a row in the block are all 0, and the current \(k\) column is 1, this row is \(\boldsymbol e_k\). Fix these positions to 1.

The recorded quantity is \(k_1\). They ensure that the corresponding item will not become an all-zero row.

## Step 2: Two simple questions on protecting other attributes

For each \(i\ne k\), define:

- \(l_i\): The number of rows outside the block that are still \(\boldsymbol e_i\);
- \(b_i\): The number of rows in the block where the \(i\) column is 1 and the rest are 0 except for \(i,k\).

If

\[
l_i<2,
\]

Just randomly select from the corresponding \(b_i\) row

\[
2-l_i
\]

position, fix the \(k\) column to 0. After this update, at least two rows remain \(\boldsymbol e_i\).

The total number of such fixed 0 positions is recorded as \(k_0\).

## Step 3: Read the column sum outside the block

Order

\[
m=
\sum_{j\notin B}q_{jk},
\]

That is, how many 1s are there in column \(k\) outside the block.

## Step 4: Free configuration within the enumeration block

Shared within the block

\[
B-k_0-k_1
\]

a free position. The final column sum is at least 3, so the number of 1's in free positions \(h\) satisfies

\[
m+k_1+h\ge3.
\]

One is uniformly selected from all free binary configurations that satisfy the constraints, and merged with fixed 0 and fixed 1 to form \(Q^\star_{k,B}\).

## Original example

The original article updates column 2 with the \(J=9,K=3,B=5\) demonstration.

- There is a \(\boldsymbol e_2\) row inside the block, so \(k_1=1\), the position is fixed to 1;
- There is only one pure question left for attribute 1 and attribute 3 outside the block, so one pure question for each of these two attributes must be protected within the block;
- Therefore the two positions are fixed to 0, \(k_0=2\);
- Column 2 outside the block already has two 1s, so \(m=2\);
- Fixed \(m+k_1=3\) has satisfied the column sum limit and all four binary combinations are possible in the remaining two positions.

The free configuration drawn by the author's example is \((0,1)\).

## Why does it always maintain three restrictions?

- The only 1 in the unit row within the block is retained, so no all-zero rows are generated;
- Keep at least two pure questions for each other attribute;
- The freely configurable lower bound ensures that the sum of columns \(k\) is at least 3;
- The column sums of other columns are not reduced;
- The two pure questions for attribute \(k\) will not be lost by updating column \(k\).

## The role of block size

Small \(B\) produces local, highly correlated moves; large \(B\) produces more distant candidates. The original pre-experiment compares \(B=K\) and \(B=2K\). The acceptance rate of the latter is higher and about 20%, so the MH of formal simulation and real data is used

\[
B=2K.
\]
